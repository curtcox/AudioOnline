Audio Online — Step 1: engine and dependency report

Status: awaiting Curt's sign-off. Nothing has been vendored and no app code exists yet. Date: 2026-10-30. Spike harness and raw results: spikes/step1/.

---

0. Requirements no candidate can meet (read first)

  1. The sandbox cannot run Web Audio. HashBin SDK v0.4.0's createSandbox() runs code only in a

classic worker inside the opaque iframe. The iframe window runs only the SDK's fixed bootstrap. OfflineAudioContext, AudioContext and AudioWorklet are undefined in that worker in all three engines (spike, §2.1). "Mix in the sandbox iframe's window" would need a new SDK mode or an app-owned frame bootstrap (Livelier does this). Proposed resolution: do all rendering in the worker with our own deterministic DSP. Native Web Audio is then used only for playback on the editor origin. This also gives better determinism (item 3).

  1. WebCodecs is not available in the sandbox worker on Chromium. Chromium reports

isSecureContext: false for the SDK's blob worker in an opaque frame, so AudioEncoder and crypto.subtle are absent. Firefox and WebKit expose them. Proposed resolution: the sandbox returns PCM, and compressed encoding runs on the editor origin. That code is ours and only processes bounded Float32Array data, never user code.

  1. Native Web Audio is not bit-exact across engines. Every node except a plain buffer copy gives

different bytes in Chromium, Firefox and WebKit. Firefox's resampler is materially different: the peak of resampled white noise is 1.31 there versus 1.94 elsewhere (§2.2). Within one engine it is repeatable. Rendering with native nodes would therefore meet the brief's per-engine rule, but never a cross-engine one.

  1. No permissive neural voice stack exists off the shelf. Every maintained browser wrapper for

Kokoro (kokoro-js), Kitten TTS (kitten-tts-js) and Piper (piper-tts-web and its forks) converts text to phonemes with eSpeak NG, which is GPL-3.0. phonemizer@1.2.1 is labelled Apache-2.0 on npm, but its 1.3 MB bundle is a compiled eSpeak NG. Upstream Piper's successor (OHF-Voice/piper1-gpl) is GPL-3.0 as well. The model weights themselves are permissive. Curt must choose one of three options: accept a GPL phonemizer that is downloaded on demand, have us write an original CMUdict-based G2P, or skip neural voices in v1 (§4.3, decision D3).

  1. eSpeak NG cannot be the bundled voice under MIT-only terms. It is GPL-3.0. The only small,

permissive bundled engine with acceptable quality is SVOX Pico (Apache-2.0). It supports 6 languages instead of 100+. Debian classes Pico's language files as non-free (§4.1).

  1. Neural-voice determinism is unverified. VITS (Piper) and Kokoro's vocoder contain random-noise

ops. Bit-exact output needs either seeded or zeroed noise inputs (to verify in Step 3) or a verified render cache keyed by (text, voice, model hash). I can't promise it yet.

  1. Not verified on real Safari. WebKit results come from Playwright WebKit 27.2. Driving Safari

would need *Allow Remote Automation*, a system setting I must not change. Historically Safari's AudioEncoder support lagged, so WAV export is the guaranteed fallback.

  1. Strudel compatibility is not on offer. Strudel is AGPL-3.0, so the pattern language must be an

original implementation of a Tidal-style mini-notation subset. It won't be Strudel-compatible.

1. Recommendation in brief

  • One sandbox worker renders everything. Python (Pyodide, only when needed) or a notation parser

produces a timeline JSON graph. An original JS renderer in the same worker realizes it with deterministic DSP. The worker returns bounded PCM (Float32Array per channel, with declared length and sample rate).

  • Deterministic DSP: only IEEE-exact operations (+ − × ÷ sqrt floor, Math.fround, Math.pow

and Math.sqrt matched too) plus our own dmath sin/cos/exp/log/tanh. Third-party JS synths (ZzFX, jsfxr) load unmodified, with a module-scope Math shadow prepended at load time, so the vendored files stay byte-identical. WASM engines (Pyodide/numpy, Pico) are already bit-exact across engines. Result: identical bytes on Chromium, Firefox and WebKit, which is stronger than the brief asks. The spike proved this for every engine-side piece we would ship (§2.2).

  • Editor origin: playback (AudioContext, started from a gesture), waveform/spectrogram, WebCodecs

encoding, and muxing with original code extended from ManimOnline's manim-video.js.

  • Pure-notation documents never load Pyodide. Parsers are about 50 KB to 0.5 MB and the first

render takes milliseconds. Python documents add about 16.4 MB of downloads and about 1.2 s of warm startup.

  • Bundled voice: SVOX Pico (Apache-2.0, 2.5 MB for en-US, bit-exact, ~30× real time). **Neural

voices on demand:** Kokoro-82M (86 MB, Apache-2.0) and/or Kitten TTS nano (24 MB, Apache-2.0) on onnxruntime-web (MIT, 14.8 MB WASM). The phonemizer depends on decision D3.

4.3 The G2P decision (D3)

  • (a) GPL phonemizer on demand. Load phonemizer@1.2.1 (compiled eSpeak NG, effectively

GPL-3.0) as a separate, unmodified, downloaded module with its own notice. Whether this is "mere aggregation" under GPL is a legal judgment for Curt. Fastest path.

My recommendation is (b), using (a) temporarily only if Curt is comfortable with it.

5. Test tolerances (follow from §2.2)

  • Rendered PCM from the worker: exact. SHA-256 of the rendered float32 PCM (and WAV export) must

match a committed golden hash on all three engines, not only within one. This applies to every gallery example except neural voices. The diagnostic checks below still run, so a mismatch is easy to read: - duration: exact sample count; - channels: exact; - silence boundaries: within ±10 ms at −60 dBFS; - peak/RMS per 100 ms window: ±0.1 dB.

  • Determinism test: render twice in one session and require byte equality.
  • Compressed exports: within-engine repeat equality only. Cross-engine checks decode the file and

compare duration to within one codec frame plus priming (Opus pre-skip 312; AAC 1024/2112) and RMS to within 1 dB.

  • Neural voices: per-engine byte equality if Step 3 shows seeded or zeroed noise works.

Otherwise, cache equality keyed by (text, voice, model hash), and tests assert duration ±5% and non-silence only.

  • Native Web Audio: not used for rendering, so there are no tolerances to set.

7. (c) audio-lite API proposal

Split: Python *describes* and JS *renders*. construct() builds a plain-JSON timeline. Raw numpy arrays travel as transferred Float32Array buffers referenced by id. The JS renderer realizes the timeline in the same worker. Notation-only documents build the same timeline directly in JS.

from audio import *

class Intro(Scene):
    sample_rate = 48000            # 44100 | 48000
    channels = 2
    seed = 1                       # all randomness derives from this
    # length = 12                  # optional; otherwise the last clip end plus effect tails

    def construct(self):
        self.say("Welcome to Audio Online.", voice="pico:en-US", track="voice")   # advances self.time
        theme = abc("X:1\nT:Theme\nK:C\nCEG c2|", instrument="pluck")
        self.add(theme, at=0.5, track="music", gain=-12).fade_in(1)
        boom = Sine(55).env(adsr(0.01, 0.2, 0, 0.3)).dur(0.6) + Noise(seed=1).lowpass(800).dur(0.3)
        self.add(boom, at=self.time, track="sfx", pan=-0.3)
        self.wait(1)
        self.track("music").fx(Reverb(room=0.4), Compressor(-18, 4)).duck(under="voice", amount=-9)
        self.master.fx(Limiter(-1))
  • Sources (nouns):

- oscillators: Sine/Square/Saw/Triangle(freq); - noise: Noise(color="white|pink|brown", seed=); - envelopes: adsr(a, d, s, r), Envelope([(t, v), …], curve=); - samples: Samples(array, rate), Sample(cid="…"), Sample("kick.wav") (uploaded file); - notation: abc(text, instrument=), zzfx([...]), sfxr(params | preset, seed=), pattern("bd*2 [~ sn] hh*4", bpm=, kit=); - speech: Speech(text, voice=); - Silence(seconds).

  • Clip operations return new clips, immutable as in Pydub:

- .dur(s), [a:b] (seconds, unlike Pydub's ms), .loop(n | until=), .gain(db), .pan(p); - .fade_in(s), .fade_out(s), .reverse(), .speed(r), .env(e); - .lowpass/.highpass/.bandpass(f, q), .fx(*effects); - a + b mixes (as in the brief's sketch, not Pydub's concatenation), a >> b sequences, a * n repeats.

  • Placement and time (Manim verbs):

- self.add(clip, at=self.time, track="main", gain=0, pan=0) returns a placement handle; - self.play(clip) adds the clip and advances self.time by its length; - self.wait(s), self.say(text, voice=, …) (equivalent to play(Speech(...))), self.time.

  • Tracks and master:

- self.track(name) supports .fx(...), .gain(db), .pan(p), .duck(under=, amount=, attack=, release=) and automation, e.g. .automate("gain", [(0, -60), (2, 0)]); - self.master takes the same effects.

  • Effects: LowPass/HighPass/BandPass/Peak/Shelf, Delay(time, feedback, mix),

Reverb(room, damp, mix) (Freeverb-style, our implementation), Compressor(threshold, ratio, attack, release, makeup), Limiter(ceiling), Gain, Drive. All of them are deterministic JS.

  • Speech length inside construct(): say() must know the utterance length synchronously.

Pico is synchronous WASM in the same worker, so a bridge synthesizes and caches during construct(). Neural voices are async, so construct() runs in a collect pass that records speech requests with estimated lengths. The app then synthesizes them and re-runs construct() (it is deterministic because seeded) until the lengths are stable, at most 3 passes. Users write ordinary synchronous code either way.

  • Source lines: every clip records its caller's line (sys._getframe) so lane clicks jump to

source. Tracebacks use the user file name with no prepended lines, as Gnuplot's diagnostics do.

  • Several Scenes in one file show a scene selector, as in ManimOnline.

11. Corrections found while building Step 3 (2026-10-30)

The Step 1 plan held, but four findings changed details. Each one has a test.

  1. ZzFX also needs a source rewrite, not only a Math shim. It uses the ** operator in four

places. No prelude can intercept **, and engines evaluate it differently. That was the real cause of the boom mismatch in §2.2. The loader rewrites exactly those four expressions to Math.pow and refuses any file whose hash or ** usage differs. The vendored file stays byte-identical.

  1. Pico keeps state between utterances. It is held in C globals that pico_resetEngine and even a

new engine leave behind, so one utterance changed the next. The WASM heap is now restored to its just-loaded snapshot before every utterance, as Gnuplot Online does around each run.

  1. jsfxr 1.4.1 emits NaN as its first sample with the platform Math too. Non-finite samples

become silence.

  1. WebKit's AAC encoder returns an ES descriptor as its "description". Chromium returns the bare

AudioSpecificConfig. The M4A muxer handles both.

Two small additions:

  • Notation documents get a transparent −1 dBFS master limiter, because sfxr's explosion preset

exceeds full scale.

  • Ducking keys on the other track after its effects and before its pan.
